# 设计稿覆盖度评估

> 对象：`enterprise-design-system` skill 的标志性设计稿（`assets/screenshots/` 15 张，覆盖菜单/维修/出差/用印/接待/用车/文件管理/人员资料等典型页面）
> 基准：现有 42 个 `m-*` / `external-*` 组件 + `styles/theme` 令牌体系
> 结论日期：2026-10-12（当日完成 P0 补齐复核）

## 0. 一句话结论

**骨架已可覆盖设计稿的绝大多数页面，剩余缺口集中在「统计可视化」与少量令牌色差。** 三个层面的缺口：

1. **8 个组件完全缺失** → **7 个已于 2026-10-12 补齐**（底部标签栏、导航栏、附件方块、文件列表、选择页、账号卡、明细卡）；**仅剩 `m-seat-grid` 车辆座位格子图**（无清晰设计稿参照，暂缓）；
2. **一批令牌色差**（成功绿/警告橙/浅蓝底/分隔线/输入底色，以及品牌蓝——品牌蓝已裁决保留 `#5192FF`）；
3. **12 处组件级偏差**（列表卡字重、标签描边、时间轴圆点、弹窗宽度、审批按钮实心/描边等）。

> 说明：下表「设计稿要求」摘自 `references/design-system.md` §2–§6；「现状」为实际读码结论。

## 四、可组合覆盖（无需新组件，约定用法即可）

| 设计稿元素 | 用现有组件组合 |
|---|---|
| 分组表单（组标题 + 白卡 + 左标签右取值 + 1px 分隔线） | `view` 标题 + `m-form` / `m-form-item` |
| 可点击选择行（值 + 浅灰 `>` 箭头） | `m-form-item :arrow` + `m-picker` / `m-datetime-picker` / `m-linkpicker` / `m-cascade-picker` |
| 任意「选项列表」页（单选/多选/卡片式） | `m-option-list`（`mode` + `indicator` + `variant`） |
| 任意「分组标题 + 内容」区块 | `m-group`（`level` 区分分组/子分组，`actionText` 提供操作位） |
| 任意「左标签右取值」信息卡 | `m-desc-list` |
| 多行文本（标签在上、输入在下） | `m-textarea` |
| 金额 / 小计行 | `m-form-item` |
| 卡片内彩色状态标签（如「行程审核中」） | `m-tag` 放 `m-card` / `m-list` slot |
| 列表页（Tabs + 搜索筛选 + 卡片流 + FAB） | `m-page-list` + `m-tabs` + `m-search` + `m-list`/`m-card` + `m-fab` |
| 提交 / 审批操作栏 | `m-button block` / `m-button-process` |
