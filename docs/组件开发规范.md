# 组件开发规范（企业推广版）

> 目标：任何业务开发者只用一套组件 API（`m-*`），视觉一致性由设计令牌保证。
> 本规范由 `node scripts/verify-convention.cjs` 机器强制执行，违规会阻断。

## 一、分层结构（谁在哪里）

```
业务页面 (pages/**)
   │  只认 m-* 组件 API，禁止出现 <uni-*> 标签，禁止 import/@import uni_modules
   ▼
领域组件层 components/m-file-*、m-linkpicker、external-*   ← 只在确有领域语义时建
   │
   ▼
通用复合层 components/m-group、m-desc-list、m-option-list、m-text-action、m-field…
   │  承载「分组 / 键值行 / 选项选择 / 文字操作」四类通用能力
   ▼
原子视觉层 styles/mixins/*.scss（indicator / icon）   ← 纯 SCSS mixin，零运行时开销
   │
   ▼
设计令牌层 styles/theme/semantic.scss（上游 melon-ui tokens.json）
```

> **⚠️ 严格策略（用户拍板，无例外）**：企业推广场景下，**任何官方组件都不得在 `m-*` 薄壳之外直接使用**——包括 `uni-icons` / `uni-scss` / `uni-transition` 这类"基础设施"也**不开放例外**。理由：一旦放开，开发者就会把带官方皮肤的 `<uni-*>` 直接敲进页面，视觉一致性瞬间崩塌。所有官方能力要复用，必须先封装成 `m-*` 薄壳并加入白名单（`ALLOWED_UNI_WRAPPERS`）。`verify-convention.cjs` 的 R1（页面全禁）+ R1b（组件仅白名单壳）已把 `<uni-*>` 标签、`import uni_modules`、`@import uni_modules` 三种路径全部拦截。

## 一之二、抽象原则（2026-10-12 用户纠正后确立，重要）

**禁止把设计稿的「页面区块 / 章节号」直接做成组件。** 设计稿 §6.x 描述的是**某一页的排版**，不是组件 API。照抄会产出只能服务一个页面的死组件。

| 反模式 | 问题 | 正确做法 |
|---|---|---|
| `m-account-card`（账号卡） | 「账号」是业务词，换场景即废 | 抽 `m-option-list variant="plain"`，账号/车辆/审批人通用 |
| `m-detail-card`（明细卡） | 组标题 + 键值行 + 增删按钮**三职责合一** | 拆成 `m-group` + `m-desc-list` + `m-text-action` |
| `m-select-list`（选择页） | 「选择页」是场景词，且与 `m-list` / `m-radio-group` 能力重叠 | 统一为 `m-option-list`，用 `mode` / `indicator` / `variant` 表达差异 |

**判断新组件该不该建的三问**：

1. **名字里有没有业务词？**（账号 / 明细 / 审批 / 单号…）有 → 说明它其实是通用件穿了业务外衣，应改抽象层级。
2. **它是否只服务一个页面区块？** 是 → 先试着用现有通用件组合；组合不了再新建，且命名必须落在通用概念上。
3. **它内部有没有 ≥2 种视觉/行为形态？** 有 → 用 prop（`mode` / `indicator` / `variant` / `level`）表达，而不是拆成多个组件。

**原子视觉一律用 SCSS mixin，不做 Vue 组件**：`styles/mixins/indicator.scss`（radio/checkbox 指示器）、`styles/mixins/icon.scss`（文件图标 / 文档 / 上传箭头 / 叉 / 加号 / 垃圾桶 / 箭头）。理由：列表里每行一个指示器时，组件化会在 mp-weixin 产生 N 个自定义组件实例（节点 + 通信开销），mixin 则是零开销且任意组件可 `@include` 复用。

> **图标约定**：本项目 iconfont 是 alicdn 远程字体，**码位无法枚举、不可信任**（猜码 = 线上出现问号/错图）。因此新增图标一律走 `styles/mixins/icon.scss` 的纯 CSS 绘制，不要猜 iconfont 码。

## 二、使用规则

| 规则 | 内容 | 强制方式 |
|---|---|---|
| R1 | 业务页面禁止直接使用 `uni-*` 组件标签、`import uni_modules` 或 `@import uni_modules`（含 uni-scss） | verify-convention.cjs |
| R1b | `uni-*` 标签 / `import` / `@import` 官方模块只允许在白名单薄壳内使用（当前：`m-datetime-picker`、`m-popup`）；**无基础设施例外** | verify-convention.cjs |
| R2 | 组件 `<style>` 禁止硬编码 hex，必须引用 `semantic.scss` 令牌；确需在 JS 字符串中写色值时，必须是 `palette.scss` 已有的令牌值 | verify-convention.cjs |
| R3 | `easycom` 必须保留 `^m-(.*)` 与 `^external-(.*)` 规则 | verify-convention.cjs |

## 三、怎么选组件

1. **交互复杂型**（弹层、日期、级联）→ 官方引擎 + `m-*` 薄壳。
   - 手法：用官方组件的**默认插槽**替换其编辑器外壳，保留点击唤起，视觉全由薄壳控制（参考 `m-datetime-picker`）。
   - 官方组件没有 `v-model` 时（如 `uni-popup`），用其事件（`@change(e.show)`）作为开关唯一事实源回灌（参考 `m-popup`）。
2. **选择场景** → 先看 `m-option-list`：`mode`（single/multiple）+ `indicator`（radio/checkbox/arrow/none）+ `variant`（card 单卡分隔线 / plain 独立卡片）已经覆盖绝大多数，不要为新场景新建「XX 选择页」组件。
3. **键值信息展示** → `m-desc-list`（配 `m-group` 作分组标题）。
4. **卡片内增删操作** → `m-text-action`（`icon="plus|trash"`、`type="primary|danger"`），不要在业务页手写带图标的文字按钮。
5. **「N 个等宽格子表达状态」形态** → `m-cell-seq`（座位占用 / 会议室选座 / 工位 / 库存格位 / 排队号）。`activeList` 传 0-based 下标数组（**不是刻度文字**），`labels` 传 `true` 用序号或传数组用自定义文案。不要为这类形态新建「XX 格子图」组件。
6. **纯展示型**（卡片、标签、字段行）→ 直接自己写，样式全部走令牌。
7. **官方样式侵入面板时**：插槽定制 > SCSS 覆盖 > fork 源码（fork 必须在本文件记录 diff，防升级丢失）。

## 四、新增组件流程

> 前置：**先按「抽象原则」三问自检**，确认不该复用现有通用件再往下走。

1. 建目录 `components/m-xxx/m-xxx.vue`（easycom 自动注册，无需 import）。
2. `<style lang="scss" scoped>` 只引用 `semantic.scss` 语义令牌（`$text-color-*` / `$color-*` / `$radius-*` / `$gray-N` / `$form-*`）。**不写硬编码 hex、不新增一次性尺寸**——组件级尺寸先加进 `semantic.scss` 再引用。
3. 图标与指示器：`@include` `styles/mixins/icon.scss` / `indicator.scss` 里的原子，**不重复实现**（更不猜 iconfont 码）。
4. v-model 约定：
   - 字段/输入类 → 标准 `modelValue` + `update:modelValue`；
   - 选择/切换类 → `:value` + `@change` 或 `v-model:value`。
5. **必须在 `pages/demo/index.vue` 加用例**，否则 `node scripts/verify-demo.cjs` 判「组件遗漏」并 `exit(1)`。
6. 跑 `node scripts/verify-convention.cjs` 和 `node scripts/verify-components.cjs`。
7. 跨端/构建相关改动必须跑 HBuilderX 三端编译（见 CLAUDE 项目记忆）。

## 五、改主题色 / 换肤

改上游 melon-ui 的 `tokens.json` → `node scripts/sync-theme.mjs` → 全部组件自动生效。
**禁止**在组件里为换肤打补丁。

## 六、常见错误

- ❌ 业务页直接写 `<uni-popup>`：绕过薄壳，弹层视觉失控，且被 R1 阻断。
- ❌ 业务页 `@import '@/uni_modules/uni-scss/index.scss'` 或 `import` 官方模块：即使是无皮肤的 uni-scss，也违反"严格策略"，必须走 `semantic.scss` 令牌；被 R1 阻断。
- ❌ 用 `<uni-icons>` 当图标：本项目图标统一用自有 `iconfont`，不引入 uni-icons 依赖。
- ❌ 组件里写 `color: #5292ff`：品牌色调整时漏改，被 R2 阻断。
- ❌ scoped 样式里定义 `placeholder-class` 类：H5 端动态占位节点匹配不到，需放到非 scoped `<style>` 块（参考 `m-textarea`）。
- ❌ 在弹层面板里用 `width: calc(100% - x)`：`uni-popup` 的 wrapper 是 flex 收缩项会塌陷，用确定值 `686rpx`（底部型 `750rpx`）。

## 八、状态管理（Pinia）

项目已引入 **Pinia** 作为「新增共享状态」的集中层（`store/app.js` 提供 `useAppStore`）。

- **定位**：跨组件共享状态（登录态、用户态、应用级配置）的单一事实源。**老代码仍走 `this.util` / `cache.js` 不受影响**；新写的共享状态请放 store，不要再散落到全局 util 或组件 data。
- **持久化**：store 复用 `utils/cache.js` 做本地缓存（写操作同时落 cache，冷启动从 cache hydrate），不重复造持久化层。
- **用法（Options API 组件内）**：
  ```js
  import { useAppStore } from '@/store/app.js'
  // 在 created / methods 里调用（需在 app.use(pinia) 之后，已就绪）
  const app = useAppStore()
  app.token          // 读
  app.isLogin        // getter
  app.setToken('x')  // 写（同步落 cache）
  app.login({ token, user })
  app.logout()       // 清 store + 清全部本地缓存
  ```
- **请勿**在组件里手动 `uni.setStorageSync` 管理登录态——统一走 `useAppStore`，保证内存态与缓存一致。
- `main.js` 已 `app.use(createPinia())`；本机未安装 pinia 时 `npm install` 即装，`verify` 脚本不受影响。

## 九、状态语义映射（m-tag type）

企业业务里状态色必须语义统一，**禁止**凭感觉用色。映射约定：

| 语义 | 颜色 | 典型场景 | m-tag `type` |
|---|---|---|---|
| 进行中 / 待审批 | 蓝（品牌） | 审批流转中 | `default` / `primary` |
| 已审核 | 绿（成功） | 通过、完成 | `success` |
| 拒绝 | 橙（警告） | 驳回、退回 | `warning` |
| 加急 / 失败 | 红（错误） | 紧急、异常 | `error` |
| 未发起 / 占位 | 灰 | 草稿、无 | 用 `$gray-*` 自绘，或 default 灰底变体 |

- `m-tag` 已内置 `type` 语义档（`success`/`warning`/`error`/`default`），直接 `<m-tag type="success">` 即可，颜色全部走令牌。
- 其他组件（m-card 状态色、m-trans、m-result）也请按此映射取色，不要硬编码 hex（被 R2 拦截）。
- 渐变 **仅** `m-banner` 一处允许使用（全 App 唯一强渐变 `$blue-500→$blue-300`），其余组件保持纯色令牌。
